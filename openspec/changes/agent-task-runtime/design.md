## Context

当前服务基于 C++11、epoll/Reactor、`EventLoop`、`TcpConnection`、`Buffer` 和线程池，但 HTTP 解析、路由、游戏业务、数据库、Etcd 和启动组装集中在 `main.cc`。当前 TCP 读取按回调粒度消费数据，不能表达半包、粘包和请求体边界；发送缓冲区和跨线程发送也存在生命周期与消费语义风险。

本变更的约束是：保留现有 Linux 网络基础设施，避免引入大型第三方框架和外部 AI 服务，优先获得可测试、可解释、可压测的系统能力。

## Goals / Non-Goals

**Goals:**

- 建立独立的 HTTP 请求、响应和路由边界。
- 支持增量解析、请求体长度限制、连接复用和协议错误响应。
- 用有界队列、worker 和状态机实现本地 Agent 任务运行时。
- 提供任务查询、取消、超时、结果回收和过载拒绝。
- 提供请求/任务指标、慢请求记录和优雅停机。
- 删除游戏业务和默认 MariaDB/Etcd 启动耦合，使服务可在无外部服务时运行。

**Non-Goals:**

- 不接入真实大模型、RAG、Agent SDK 或外部推理服务。
- 不实现分布式任务调度、持久化任务队列或多节点一致性。
- 不重写现有 Reactor 为真正的 io_uring 收发模型。
- 不引入 Docker、Kubernetes、消息队列或新的 Web 框架。
- 不承诺 HTTP/1.1 全部特性；chunked 编码和复杂 JSON 解析不在第一阶段范围内。

## Decisions

### 1. 先修复协议边界，再接入任务运行时

`TcpConnection` 继续负责 socket 和连接级缓冲，但业务回调只接收已经完成的 HTTP 请求。`HttpParser` 持有解析状态和未完成请求，解析结果以明确状态返回：需要更多数据、请求完成、协议错误、请求过大。

选择增量状态机而不是对完整字符串重新扫描，因为 TCP 没有消息边界，状态机可以保留半包状态并避免业务层消费不完整数据。第一阶段使用 `Content-Length`，对不支持的传输编码返回明确错误。

### 2. 用 Router 和 Handler 替代 main.cc 中的业务 if/else

路由表按 HTTP 方法和路径匹配 Handler。`main.cc` 只负责创建 EventLoop、组装服务对象、注册路由和启动生命周期。游戏 Handler、数据库连接池、Etcd 客户端从默认服务中删除。

选择显式路由表而不是继续增加条件分支，因为路由行为需要独立测试，也需要让 Agent 任务接口与网络层解耦。

### 3. Agent 采用单机有界任务运行时

任务运行时由任务 ID、任务状态、固定容量队列、固定数量 worker、结果表和取消/超时控制组成。任务处理不得直接阻塞 IO 线程；worker 完成后通过 `EventLoop::queueInLoop` 更新状态并触发等待连接的响应。

队列满时立即返回 429 或 503，任务超时转为终态并回收结果资源。第一阶段任务执行器只注册本地同步任务，例如健康检查、系统信息和内存池基准；不引入远程执行和真实模型。

### 4. 观测使用进程内固定指标

使用原子计数器记录请求、错误、连接、任务状态和队列数据；延迟使用固定桶统计，慢请求写入有界环形缓冲区。通过 `/metrics` 和 `/slowlog` 提供文本或 JSON 查询。

选择固定桶和有界缓冲区而不是引入完整 Prometheus SDK 或日志系统，因为当前目标是证明指标语义、资源上界和故障定位路径，同时保持 C++11 构建简单。

### 5. 优雅停机由 EventLoop 统一驱动

信号处理只负责通知 EventLoop，不在异步信号处理函数中执行复杂逻辑。EventLoop 收到停机请求后停止 Acceptor，拒绝新任务，等待现有任务和连接排空；达到超时后关闭剩余资源并退出。

选择统一生命周期管理而不是让 `main` 直接销毁对象，因为连接、任务 worker 和定时器分别属于不同线程/事件循环，必须先改变接收状态再回收资源。

## Risks / Trade-offs

- [现有代码存在用户未提交修改和生成物] -> 实现前只修改源码与测试目标，保留其他工作区变化，不把 `build/`、`bin/`、`lib/` 和日志纳入变更。
- [HTTP keep-alive 和多个请求处理复杂] -> 第一阶段只支持顺序请求，解析器每次只产出一个请求，剩余字节留在输入缓冲区。
- [任务取消可能无法中断已运行的同步任务] -> 取消先定义为状态取消；任务函数通过取消令牌主动检查，不能强行终止 worker 线程。
- [数据库和 Etcd 删除可能影响旧脚本] -> 将新服务入口改为无外部依赖启动，并把旧游戏启动方式视为破坏性变更，不保留隐式兼容路径。
- [指标统计会增加共享原子开销] -> 仅使用必要的原子计数和固定桶，后续通过 benchmark 验证热点，不预先声称性能收益。
- [停机排空可能被慢任务阻塞] -> 增加明确停机超时和终态清理，测试任务排空、超时关闭和重复信号。

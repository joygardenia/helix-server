## Why

当前项目的 HTTP 入口、游戏业务、数据库、服务发现和服务器启动逻辑集中在 `main.cc`，项目虽然能够展示 epoll、Reactor 和线程池，但缺少清晰的协议边界、任务执行模型、资源上限和故障观测能力。需要在不重新引入大型外部项目的前提下，把它收敛为一个能够体现 Linux/C++ 系统工程能力的任务服务运行时。

## What Changes

- **BREAKING** 将游戏业务路由和游戏数据库依赖从默认服务中移除。
- 拆出增量式 HTTP 请求解析和独立路由层，正确处理半包、粘包、请求体长度和连接生命周期。
- 增加有界 Agent 任务运行时，支持任务提交、查询、取消、超时、结果回收和队列满时的明确拒绝。
- 增加本地任务注册机制，提供健康检查、系统信息和内存池基准等可验证任务，不接入外部大模型 SDK。
- 增加请求与任务指标、慢请求记录和过载保护接口。
- 增加信号触发的优雅停机，停止接收新连接并排空已有连接和任务。
- 增加协议、路由、任务状态机、资源耗尽和停机行为的自动化测试。

## Capabilities

### New Capabilities

- `http-protocol`: 增量 HTTP 请求解析、连接复用和协议错误处理。
- `agent-task-runtime`: 有界任务队列、任务状态机、取消超时、结果查询和本地任务注册。
- `observability-overload`: 请求/任务指标、慢请求记录、请求限制和过载拒绝。
- `graceful-shutdown`: 信号处理、停止接入、连接排空、任务排空和资源退出。

### Modified Capabilities

- 无

## Impact

- 影响 `src/main.cc`、`src/TcpConnection.cc`、`src/Buffer.cc`、`include/Buffer.h`、`src/TcpServer.cc` 和事件循环相关代码。
- 新增 HTTP、路由、任务运行时、指标和停机管理模块及其测试目标。
- 默认构建不再依赖 MariaDB、Etcd 或游戏数据库；外部依赖只保留确有必要的现有系统库。
- 对现有服务启动方式和游戏路由产生破坏性变化，需要同步调整运行脚本和测试入口。
